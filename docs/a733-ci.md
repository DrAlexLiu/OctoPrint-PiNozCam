# A733 AWNN runtime CI

## Status

`build-a733-runtime.yml` is intentionally self-hosted only. Radxa documents the
A733 `vpm_run` path using the public `ZIFENG278/ai-sdk` repository and the
`AI_SDK_PLATFORM=a733` build target. PiNozCam pins the reviewed SDK input to
commit `fc90006d0f6569da2f6726c2d8395877686f5aca` rather than following a moving
branch.

The public repository contains the technical AWNN/VIPLite inputs needed by the
build:

- `awnn_lib.c`, `awnn_lib.h`, `awnn_quantize.c`, `awnn_quantize.h`
- `vip_lite.h`
- `libNBGlinker.so`, `libVIPhal.so`

`src/allwinner/build.sh` requires `AWNN_SDK_DIR`, `VIP_INCLUDE_DIR` and
`VIP_LIB_DIR` to point to those external artifacts. A GitHub-hosted ARM64
runner still cannot execute the resulting NPU program; the final inference test
must run on A733 hardware.

Public source availability is not the same as permission to redistribute the
compiled result. The reviewed SDK repository has no root license, and its
VIPLite header contains proprietary and confidential-use language. Do not
attach the A733 Wheel to a public release until an explicit license grant or
written redistribution permission has been confirmed.

`bootstrap_ci.sh` records the approved vendor input set as eight SHA-256
digests and fails closed if any source, header, or library changes. Updating an
A733 SDK therefore requires an intentional digest review instead of silently
changing the output behind the same PiNozCam commit.

## Manual self-hosted workflow

Use manual trigger:

- `workflow_dispatch` with:
  - `awnn_sdk_dir`: absolute path to the checked-out vendor SDK directory
    (usually containing `libawnn_viplite`).
  - `version`: runtime version to encode in the wheel.
- Runner labels: `[self-hosted, linux, ARM64, a733]`.

The workflow executes:

1. A GitHub-hosted ARM64 job builds the static ExecuTorch CPU fallback from
   the pinned public source revision and uploads it as a one-day intermediate
   artifact.
2. The A733 job downloads that artifact and the SHA-256-pinned model payloads
   from the previous public PiNozCam release.
3. `src/allwinner/bootstrap_ci.sh`
   - validates SDK and VIPLite headers/libs,
   - builds `runtime-artifacts/bin/nozcam_daemon.awnn.aarch64` without copying
     any vendor source or library into the repository or Wheel.
4. `python3 src/runtime/package_accelerator_runtime.py --target awnn --artifact-root runtime-artifacts --output dist --version "$version" --revision "$GITHUB_SHA"`
5. Wheel verification:
   - both daemon and wheel `file` checks,
   - install wheel into a temp location,
   - verify both runners and both models exist in the runtime package,
   - run a real protocol inference through both the CPU and AWNN runners,
   - verify `dist/SHA256SUMS`.
6. Upload `dist/*.whl` and `dist/SHA256SUMS` with retention `14` days.

The resulting Wheel uses the platform tag `linux_aarch64`, not a manylinux
tag. The AWNN executable intentionally relies on the board-provided
`libNBGlinker.so` and `libVIPhal.so`; those vendor libraries are outside the
manylinux policy allowlist and are not redistributed in the Wheel. Once the
runner's redistribution permission is confirmed, this artifact belongs on the
matching immutable GitHub Release.

## Driver and user-space library compatibility

The two vendor libraries are not independent of the NPU driver:

```text
PiNozCam AWNN runner
  -> libNBGlinker.so
  -> libVIPhal.so
  -> /dev/vipcore
  -> A733 VIP9000 kernel driver and NPU
```

`libVIPhal.so` is the user-space hardware abstraction layer. Bundling an
arbitrary SDK copy in the Wheel could override a board image's matched library
and create an ioctl/ABI mismatch with its kernel module. PiNozCam therefore
uses the copies installed by the board image under `/usr/local/lib`, just as
the Rockchip runner uses the board's `librknnrt.so`.

The 2026-08-09 qualification board ran kernel `5.15.147-21-a733`, exposed
`/dev/vipcore`, and completed a real inference with the exact v2.0 SDK library
hashes pinned by `bootstrap_ci.sh`. That proves the tested combination, not all
future board images. Release smoke tests must continue to load the system
libraries and execute a real NPU inference; a missing or incompatible runtime
must cause a clean CPU fallback.

## Expected model path conventions

The CI verifies the source Wheel digest before extracting `nozcam-a733.nb`
and `nozcam-cpu.pte`. These filenames match the runtime names expected by the
plugin. The previous release supplies immutable model inputs only; both
executables are rebuilt by this workflow from the checked-out source.
