# A733 AWNN runtime CI

## Status

`build-a733-runtime.yml` is intentionally self-hosted only.

GitHub-hosted ARM64 runners do not provide a public, pinned, redistributable
AWNN/VIPLite input set for this project:

- `awnn_lib.c`, `awnn_lib.h`, `awnn_quantize.c`, `awnn_quantize.h`
- `vip_lite.h`
- `libNBGlinker.so`, `libVIPhal.so`

`src/allwinner/build.sh` also requires `AWNN_SDK_DIR`, `VIP_INCLUDE_DIR` and
`VIP_LIB_DIR` to point to external artifacts. These files are vendor-proprietary
by design and cannot be copied into this repository or fetched from a pinned public
index for an honest hosted build.

`bootstrap_ci.sh` records the approved vendor input set as eight SHA-256
digests and fails closed if any source, header, or library changes. Updating an
A733 SDK therefore requires an intentional digest review instead of silently
changing the output behind the same PiNozCam commit.

## Manual self-hosted workflow

Use manual trigger:

- `workflow_dispatch` with:
  - `awnn_sdk_dir`: absolute path to the checked-out vendor SDK directory
    (usually containing `libawnn_viplite`).
  - `version`: runtime version to encode in the wheel.
- Runner labels: `[self-hosted, linux, ARM64, a733]`.

The workflow executes:

1. A GitHub-hosted ARM64 job builds the static ExecuTorch CPU fallback from
   the pinned public source revision and uploads it as a one-day intermediate
   artifact.
2. The A733 job downloads that artifact and the SHA-256-pinned model payloads
   from the previous public PiNozCam release.
3. `src/allwinner/bootstrap_ci.sh`
   - validates SDK and VIPLite headers/libs,
   - builds `runtime-artifacts/bin/nozcam_daemon.awnn.aarch64` without copying
     any vendor source or library into the repository or Wheel.
4. `python3 src/runtime/package_accelerator_runtime.py --target awnn --artifact-root runtime-artifacts --output dist --version "$version" --revision "$GITHUB_SHA"`
5. Wheel verification:
   - both daemon and wheel `file` checks,
   - install wheel into a temp location,
   - verify both runners and both models exist in the runtime package,
   - run a real protocol inference through both the CPU and AWNN runners,
   - verify `dist/SHA256SUMS`.
6. Upload `dist/*.whl` and `dist/SHA256SUMS` with retention `14` days.

The resulting Wheel uses the platform tag `linux_aarch64`, not a manylinux
tag. The AWNN executable intentionally relies on the board-provided
`libNBGlinker.so` and `libVIPhal.so`; those vendor libraries are outside the
manylinux policy allowlist and are not redistributed in the Wheel. The same
reason means this artifact belongs on a GitHub Release unless those
dependencies are later bundled with confirmed redistribution rights.

## Expected model path conventions

The CI verifies the source Wheel digest before extracting `nozcam-a733.nb`
and `nozcam-cpu.pte`. These filenames match the runtime names expected by the
plugin. The previous release supplies immutable model inputs only; both
executables are rebuilt by this workflow from the checked-out source.
