# A733 AWNN runtime CI

## Hosted build boundary

`build-a733-runtime.yml` runs entirely on GitHub-hosted ARM64 infrastructure.
It does not register, contact, or require a self-hosted A733 runner.

[Radxa's A733 documentation](https://docs.radxa.com/cubie/a7a/app-dev/npu-dev/cubie-vpm-run)
uses the public [`ZIFENG278/ai-sdk`](https://github.com/ZIFENG278/ai-sdk)
repository for VIPLite applications. PiNozCam fetches the exact commit
`fc90006d0f6569da2f6726c2d8395877686f5aca` and verifies the SHA-256 digest of
all eight build inputs before compiling:

- `awnn_lib.c`, `awnn_lib.h`, `awnn_internal.h`
- `awnn_quantize.c`, `awnn_quantize.h`
- `vip_lite.h`
- `libNBGlinker.so`, `libVIPhal.so`

The AWNN daemon is compiled in a digest-pinned Ubuntu 20.04 ARM64 container.
The public `libNBGlinker.so` itself imports `GLIBC_2.29`, so an older glibc
cannot link it. The workflow rejects a daemon whose imported GLIBC version
exceeds 2.29, verifies its AArch64 ELF metadata and direct and transitive
dynamic dependencies, and rejects an ephemeral CI path in its runtime search
path.

The resulting Wheel remains tagged `linux_aarch64`, not manylinux. The daemon
intentionally depends on the A733 image's `/usr/local/lib/libNBGlinker.so` and
`/usr/local/lib/libVIPhal.so`; these vendor libraries are not bundled in the
Wheel and are outside the manylinux policy allowlist.

## What the workflow verifies

The hosted workflow:

1. builds the static AArch64 ExecuTorch CPU fallback;
2. fetches and verifies the pinned SDK and model inputs;
3. compiles and links `nozcam_daemon.awnn.aarch64`;
4. verifies ELF architecture, GLIBC ceiling, NEEDED entries, and runtime path;
5. packages the A733 runner, CPU fallback, and two models;
6. verifies Wheel metadata, manifest, payload, and SHA-256;
7. runs PING, INFO, INFER, and SHUTDOWN through the CPU fallback; and
8. uploads the Wheel and checksum as GitHub Actions artifacts.

The workflow does not execute an A733 NPU inference. GitHub-hosted runners do
not expose `/dev/vipcore`, and the release pipeline has no self-hosted hardware
job. Its A733 evidence is therefore a reproducible hosted build plus static and
packaging verification, not a per-release NPU smoke test.

## Driver and system-library boundary

The runtime path on a board is:

```text
PiNozCam AWNN runner
  -> /usr/local/lib/libNBGlinker.so
  -> /usr/local/lib/libVIPhal.so
  -> /dev/vipcore
  -> A733 VIP9000 kernel driver and NPU
```

`libVIPhal.so` is the user-space hardware abstraction layer. Bundling a random
copy in the Wheel could override the board image's matched library and create
an ioctl/ABI mismatch with its kernel module. PiNozCam therefore links against
the pinned SDK copy during CI but records `/usr/local/lib` as the production
runtime path.

If the board runtime or NPU initialization is unavailable, PiNozCam must fail
the AWNN warm-up cleanly and use the CPU fallback contained in the same Wheel.

## Redistribution note

Public source availability is not by itself a redistribution license. The
reviewed SDK repository has no root license and `vip_lite.h` contains
proprietary wording. The workflow can compile and retain a private Actions
artifact, but publishing that derived A733 Wheel requires the maintainer to
resolve the redistribution terms first.
